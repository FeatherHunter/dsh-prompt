# 方向信号统一为整机（读），视口仅回落

**状态**：accepted（2026-10-02，#110 检测统一。用户原话：关时检测实际方向并选中；`auto` 现状“功能缺失”。）

## 背景

- 桌面浏览器视口恒横屏，`auto` 跟视口等于恒横屏——在远程（手机）场景下是错误信号（ADR-0002：插件观测不到手机朝向，视口与手机无关）。
- 整机桥（`GET /_dsh/dsh-prompt/system/orientation`）已是自有读能力：锁定、进入快照本就依赖它。再为显示另起信号源等于两套真相。
- 读与写不对称：读可缓存回落，写必须串行确认（本仓整机桥 verify+回滚既有）。

## 决定

1. **有效方向** = 显式偏好赢；`auto` 取环境方向缓存（整机桥已知值），缺席/非法回落视口推导。纯函数 `resolveEffectiveOrientation(pref, env, viewport)`，面板与设置页共用。
2. **环境缓存**住客户端远程偏好模块（内存态，附来源与时间戳）：设置页挂载预热、开远程复用进入查询、锁定/恢复成功复用已知结果——**零新增 spawn**。hover/面板只读缓存，永不触发网络；桥确认缺席记负缓存，本会话不再做推测性查询（用户显式锁定不受影响）。
3. **显示有效值+来源**：设置页方向行下加一行「当前：横屏（整机）/视口」，开关态同规；偏好本身不动（检测只读真值，不写真值）。
4. **每层只恢复自己的进入值**：偏好↔偏好，会话快照（#110 已落地）不动；OS↔OS。历史污染的显式偏好不做静默迁移（分不清意图），靠切回自动一次自愈。

## 考虑过的选项

- **维持 auto 跟视口**——保留一个桌面恒等式，`auto` 继续名存实亡；且与“锁定先切整机”分属两个信号源，心智分裂。否决。
- **检测到啥就写偏好**——把一次读变成永久选择，污染存量、且与会话恢复打架（恢复的是检测 artifact 而非用户选择）。否决。
- **会话覆盖改内存态（先存后恢改纯临时）**——更纯，但存量默认从此改不动（关时按钮禁用、开时全变临时），且外部直写路径全要适配。否决（见 #110 讨论），修进入值质量才是病根。
- **缓存轮询刷新/TTL**——自发翻转布局比滞后更惊；新鲜度由用户动作事件界定。否决。
- **手机朝向感知**——按 ADR-0002 不可观测。排除。

## 后果

- `CONTEXT.md` 方向偏好/自适应布局定义同步更新；设置页 hint 改“自动跟整机方向，无桥时跟视口”。
- 面板挂载必须是零 OS 调用（回归断言）；设置页挂载恰一次预热 GET。
- 真机验收仍需：整机横竖各转一次，确认有效值 caption 来源角标与格子同步。
