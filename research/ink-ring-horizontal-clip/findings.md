# 描边环的**横向**裁切：每行第一个字左缘缺一截（issue #176）

- 日期：2026-10-20；方法：只认一手来源 —— 真组件渲染结果（react-test-renderer 挂真 `TemplateBrowser`）、headless Chrome 逐列像素、报告人真机截图。
- 问题：`research/ink-stroke-rendering.md` §2.2 第 3 条给出横向补偿的配方，并判定横向损失「视觉上可忽略」（实测左侧带 0 个实心像素、11 个 AA 像素）。**本篇证伪那个「可忽略」**：在报告人真机（Windows 缩放 175%）上，它看得见。
- 范围：只回答「环的左缘为什么缺、缺多少、怎么补、补了会不会位移」；描边技术选型、色值口径、主题跟随见前篇与 ADR-0007。
- 关联：`research/ink-stroke-rendering.md`（描边技术与裁切的原件）、`docs/adr/0007-template-color-is-user-data.md`（颜色=用户数据）、`research/ink-render-evidence.md`（四面渲染证据表）。

## 0. 结论速览（事实）

1. **机制**：描边是八向 1px `text-shadow`，环画在字形**外侧**；裁切盒（`overflow:hidden`）按 **padding box** 裁 ⇒ 落在盒外的那 1px 直接消失。纵向早前已补（`padding-block:2px; margin-block:-2px`），**横向没补** ⇒ 每行第一个字左缘的环被削掉。
2. **量级**：同一行里，第一个字左缘的环比它右缘、比同行其它字都薄。报告人截图实测：首行「全」左侧 3px 带内非背景像素 **15**，同一字右侧 **66**，同行第二字左侧 **63**。
3. **真组件复现**：100% 缩放下首字左缘保留率 **0%**（整列被裁）；175% 缩放下 **52%**（子像素位置让描边骑在裁切线上，只保住一半）⇒ 正是「隐约少了几个像素点」。
4. **谁会中招**：只有当第一个字**字形左边界离文字原点不到 1 CSS px** 时才会被切 —— 宽体 CJK 字（全面升级 / 版本发布 / TS…）与拉丁字母会；字形居中的窄字（如「自」，左边界本就有余量）左侧环完好。**所以不是「每一行」都缺，而是「每行第一个字的左缘，按字形而定」。**
5. **修法与代价**：裁切盒内补 `padding-inline:1px` + 同量负 `margin-inline:-1px` ⇒ 环的左半圈回到裁切矩形内，**文字不位移、盒的外框尺寸不变**（正负等量抵消），代价是行内兄弟文本少 2px 宽度（`flex:1 1 auto` 的简介吸收）。修后 100% / 175% 两档保留率均 **100%**，文字 x 位置不变（32→32、57→57 设备像素）。

## 1. 机制：为什么是「第一个字的左缘」

名字节点在四个面里的宿主关系：

| 面 | 名字节点 | 谁裁它 |
|---|---|---|
| 悬浮小列表（Hover List） | 行内裁切宿主的**第一个**子节点 | 宿主（`overflow:hidden`） |
| 设置页列表 | 名字节点自带 `overflow:hidden`（`nmStyle`） | 自己 + 行的裁切盒 |
| 远程大列表卡片标题 | 标题自带 `overflow:hidden` | 自己 |
| 智能卡行名 | 行名自带 `overflow:hidden` | 自己 |
| 取色浮层真名预览 | 预览名自带 `overflow:hidden` | 自己 |

⇒ 悬浮小列表那一处尤其显眼：名字**紧贴**裁切宿主的左缘，字形左边界离文字原点不到 1px 时，1px 描边副本整体越界 ⇒ 首字左缘的环全没。

## 2. 像素证据

### 2.1 报告人真机截图（原件 1000×703，环色 = 宿主正文令牌 #f9fafb，底色 #0a0a0a）

取每行第一个字的字形包围盒，量其左/右两侧 3px 带内的非背景像素数：

| 行 | 名字颜色 | 首字左侧 | 首字右侧 | 同行第二字（对照）左侧 |
|---|---|---|---|---|
| 1 | #ad5cff | **15** | 66 | 63 |
| 2 | #009400 | 66 | 66 | 66 |
| 3 | #4a9400 | **20** | 57 | 59 |
| 4 | #ed2121 | **24** | 33 | 32 |
| 6 | #1380ec | **5** | 45 | 40 |

第 2 行不缺：它的首字「自」字形居中，左边界离文字原点够远 ⇒ 与 §0 第 4 条一致。

### 2.2 真组件复现（可重跑）

1. `react-test-renderer` 挂真组件 `TemplateBrowser`（`compact: true` = 悬浮小列表），塞一个带色自定义模板 ⇒ 取出真组件渲染出的行内样式（不手抄）。
2. 把那一行序列化成 HTML（保留全部行内样式），另出一个 `overflow:visible` 的对照变体（= 不裁时的真值）与一个补了横向补偿的变体。
3. headless Chrome `--force-device-scale-factor=1 / 1.75` 渲染，Python 逐列量「第一个字字形包围盒左侧 1 CSS px 带」内的非背景像素。
4. 判据：裁切变体保留率 = 该带像素 / 对照变体该带像素。

| 变体 | 100% 缩放 | 175% 缩放 |
|---|---|---|
| 修前（裁切盒无横向余量） | 0 / 6 = **0%** | 17 / 33 = **52%** |
| 修后（`padding-inline:1px` + `margin-inline:-1px`） | 6 / 6 = **100%** | 33 / 33 = **100%** |

字形左缘 x 位置修前修后一致（100% 档 32→32、175% 档 57→57 设备像素）⇒ **文字不位移**。

## 3. 修法

与纵向补偿同构，落在**裁切盒**上（不是名字 span —— 外层还裁的话，内层 span 的内边距不改变外层的裁切矩形，见前篇 §2.2 第 1 条）：

- 裁切盒（名字自身是裁切盒的四处 + 悬浮小列表的裁切宿主）：`padding-inline:1px; margin-inline:-1px`。
- 悬浮小列表的名字节点**自己不加**（它不是裁切盒，加了既无效又会把文字推 1px）。
- 条件与纵向一致：**有颜色才补**；未上色的行逐字段不变。
