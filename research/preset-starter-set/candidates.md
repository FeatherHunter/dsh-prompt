## 候选模板（18 个）

### 场景标签：思考框架（10）

#### 1. 第一性原理拆解 / First Principles
- **场景标签**：思考框架
- **适用场景**：复杂问题归因、创新思考、突破既有框架时
- **正文**：
\`\`\`
请用第一性原理分析 [主题]：
1. 这个问题的基本组成单元是什么？
2. 哪些是真正不可改变的真理（而非假设）？
3. 如果去掉所有既有假设，问题本身还剩下什么？
4. 有哪些被大多数人默认为常识、但其实可以颠覆的？
5. 基于以上推演，给出你的原创见解，并说明它与主流看法的差异。
\`\`\`

#### 2. 苏格拉底式追问 / Socratic Questioning
- **场景标签**：思考框架
- **适用场景**：厘清思路、发现思维盲区、重大决策前
- **正文**：
\`\`\`
请用苏格拉底式追问帮助我思考 [主题]：
1. 先复述我当前的观点或核心假设；
2. 提出 3 个最有力的质疑；
3. 找出一个我尚未考虑到的视角；
4. 如果你是深思熟虑的对话者，你会问我哪几个我没想到的问题？
5. 追问结束后，把整个过程浓缩成一个更精准的问题。
\`\`\`

#### 3. 深度多维分析 / Deep Analysis
- **场景标签**：思考框架
- **适用场景**：对某个概念、问题或决策需要深入剖析时
- **正文**：
\`\`\`
请从多个维度深度分析 [主题]：
1. 本质是什么？
2. 有哪些常见的误解？
3. 支持和反对的证据分别是什么？
4. 这个问题的边界在哪里（什么情况下它不再成立）？
5. 如果你必须做出一个判断，会是什么？
6. 你最强的那个结论，弱点在哪里？
\`\`\`

#### 4. 对抗式审查 / Adversarial Review
- **场景标签**：思考框架
- **适用场景**：验证方案/结论是否经得起最严格的反驳（红队思维）
- **正文**：
\`\`\`
请对以下 [方案/结论] 做对抗式审查（红队角色）：
1. 找出其中最强的 5 个假设，逐一论证它们可能如何失效；
2. 构造最可能推翻它的 3 个反例或失败场景；
3. 指出其中隐藏的认知偏差与利益相关方视角的盲区；
4. 给出「如果这个方案失败，最可能的原因是什么」的排序清单；
5. 最后给出：在何种条件下你才会认为它是错的——以及何种证据能让你改变立场。
[方案/结论]：
\`\`\`

#### 5. 决策博弈分析 / Decision Analysis
- **场景标签**：思考框架
- **适用场景**：在多个选项间纠结、需要权衡利弊时
- **正文**：
\`\`\`
你是一位冷静的决策分析师。请分析我的处境：
1. 列出每个选项最坏的结果是什么；
2. 每个选项最好的结果是什么；
3. 最可能的结果是什么；
4. 如果 10 年后回头看，我可能会后悔什么；
5. 有没有哪条路是「没有回头路」的；
6. 最后给出你本人的选择，并说明理由；再指出我的处境里我可能忽略的第三个选项。
我的处境：[描述选项与背景]
\`\`\`

#### 6. 事前验尸 / Pre-mortem
- **场景标签**：思考框架
- **适用场景**：方案启动前，提前暴露失败风险
- **正文**：
\`\`\`
假设 [方案/项目] 已经在一年后彻底失败了。请以「事后回溯」的方式写一份失败分析：
1. 按可能性从高到低列出 8 个失败原因；
2. 对前 3 个原因，给出现在就能做的预防措施；
3. 指出哪些早期信号现在就该监控；
4. 最后说明：这个方案是否从一开始就有致命缺陷。
方案描述：[方案]
\`\`\`

#### 7. 费曼技巧 / Feynman Technique
- **场景标签**：思考框架
- **适用场景**：检验自己是否真正理解一个概念，或向他人讲清一个概念
- **正文**：
\`\`\`
请用费曼技巧帮我确认是否真正理解了 [概念]：
1. 用最简单的语言、面向完全不懂的人解释这个概念（禁止术语）；
2. 给出 2 个生动类比和 2 个反例；
3. 指出我下面理解中的错误或不准确之处：[贴出我的理解]；
4. 设计 3 个判断题检验我是否真的懂了。
\`\`\`

#### 8. 五个为什么 / Five Whys
- **场景标签**：思考框架
- **适用场景**：追根究底、定位表面问题背后的根因
- **正文**：
\`\`\`
针对问题 [问题描述]，请连续追问五个「为什么」，每层基于上一层的事实回答：
1. 为什么会发生 [问题]？
2. （针对原因）为什么会这样？
3. （继续深入）为什么？
4. （继续深入）为什么？
5. （继续深入）为什么？
最后：区分哪些是根本原因、哪些只是表层触发因素，并给出针对根本原因的解决方向。
\`\`\`

#### 9. MECE 拆解 / MECE Decomposition
- **场景标签**：思考框架
- **适用场景**：把模糊的大问题拆成相互独立、完全穷尽的子问题
- **正文**：
\`\`\`
请用 MECE 原则拆解 [问题]：
1. 给出 3~6 个相互独立（Mutually Exclusive）的分类维度；
2. 每个维度下列出所有子项，确保完全穷尽（Collectively Exhaustive）；
3. 指出拆解中可能的遗漏与重叠；
4. 给出按重要性排序后的关键子问题清单。
\`\`\`

#### 10. 认知偏差检查 / Cognitive Bias Check
- **场景标签**：思考框架
- **适用场景**：审查自己的推理、计划或结论是否被认知偏差污染
- **正文**：
\`\`\`
请审查以下 [推理/计划/结论] 中的认知偏差：
1. 列出可能影响它的偏差（确认偏误、沉没成本、可得性、锚定、乐观/悲观偏差、群体思维等），并指出具体证据；
2. 对每条偏差，给出「如何检验是否真的受影响」的方法；
3. 给出一个反事实检验：如果结论被证明是错的，最可能因为哪条偏差？
[推理/计划/结论]：
\`\`\`

### 场景标签：学习（2）

#### 11. 学习路线设计 / Learning Path
- **场景标签**：学习
- **适用场景**：从零开始掌握一个领域，或补足某个技能
- **正文**：
\`\`\`
请为 [领域/技能] 设计一条从零到可实战的学习路线：
1. 按阶段拆分（入门→进阶→实战），每个阶段给出学习目标；
2. 每个阶段推荐 2~3 个核心主题和练习方式；
3. 指出常见的「伪学习陷阱」（只收藏不练习等）；
4. 给出一个 30 天内可完成的最小闭环，以及检验掌握程度的基准。
背景（可选）：我的当前水平 [水平]，目标 [目标]
\`\`\`

#### 12. 概念澄清 / Concept Clarification
- **场景标签**：学习
- **适用场景**：快速理解一个新概念，辨析相近概念
- **正文**：
\`\`\`
请帮我彻底理解 [概念]：
1. 一句话定义 + 一个最小例子；
2. 它与 [相近概念A] / [相近概念B] 的本质区别是什么（各给一个对比场景）；
3. 这个概念在什么情况下不适用（边界）；
4. 给出 3 个由浅入深的练习场景让我检验理解。
\`\`\`

### 场景标签：工程（4）

#### 13. 代码审查 / Code Review
- **场景标签**：工程
- **适用场景**：提交前或接手前审查一段代码
- **正文**：
\`\`\`
请审查以下代码（附上下文 [代码/文件/技术栈]）：
1. 正确性：潜在 bug、边界条件、并发/异步问题；
2. 安全：注入、鉴权、敏感信息、依赖风险；
3. 可维护性：命名、结构、重复、可读性；
4. 性能：明显的低效点；
5. 按严重程度排序输出，并给出每个问题的具体修改建议（含示例代码）。
\`\`\`

#### 14. 测试用例设计 / Test Design
- **场景标签**：工程
- **适用场景**：为功能/模块设计覆盖充分的测试
- **正文**：
\`\`\`
请为以下功能设计测试用例：[功能描述]
1. 正常路径用例（含输入/预期输出）；
2. 边界与极端值用例；
3. 异常与错误处理用例；
4. 并发/重复/幂等场景（如适用）；
5. 指出哪些用例最容易漏、以及对应的风险。
\`\`\`

#### 15. 重构方案 / Refactoring Plan
- **场景标签**：工程
- **适用场景**：在保持行为不变的前提下改进代码结构
- **正文**：
\`\`\`
请为以下代码提出重构方案：[代码/模块]
1. 指出当前结构的主要问题（职责、耦合、可测试性）；
2. 给出目标结构（抽象与拆分建议，含示例）；
3. 按「小步重构」顺序列出步骤，每一步可独立提交且行为不变；
4. 指出哪些重构有风险、需要测试保护。
\`\`\`

#### 16. 解释代码 / Explain Code
- **场景标签**：工程
- **适用场景**：读懂一段陌生代码、向他人讲解
- **正文**：
\`\`\`
请解释以下代码：[代码]
1. 这段代码做什么（一句话）；
2. 逐段讲解执行流程与关键数据结构；
3. 指出其中「为什么这样写」的设计取舍；
4. 指出潜在问题与改进点；
5. 用一句话概括它在我更大的系统里扮演的角色。
\`\`\`

### 场景标签：执行（2）

#### 17. 盲区检查 / Blind Spot Pass
- **场景标签**：执行
- **适用场景**：启动一件重要事情前，检查遗漏的风险与变量
- **正文**：
\`\`\`
在我开始 [任务] 之前，请帮我做一次盲区检查：
1. 我可能遗漏的关键变量有哪些？
2. 潜在的风险与最容易忽略的影响因素？
3. 哪些点需要提前决策、哪些可以后置？
4. 给我一个 3 分钟内可完成的快速检查清单。
我的计划：[计划/目标/约束]
\`\`\`

#### 18. 零丢失快照 / Zero-loss Snapshot
- **场景标签**：执行
- **适用场景**：长会话/项目中途，把信息完整固化以防丢失
- **正文**：
\`\`\`
请执行一次「零丢失快照」：
1. 把我们从会话开始至今的关键信息，按「目的地 / 约束与偏好 / 已确认的决定 / 待决问题 / 雾区（隐约可见但还不清晰）」五类逐条列出——不压缩、不合并，宁可啰嗦不可省略；
2. 每条标注出处（引用我原话）；
3. 单独列一节「可疑遗漏」：凡是我提过但你觉得与主线无关、太模糊或像执行细节而没纳入的，全部摆出并写明理由；
4. 列完后停下等我逐条核对，确认后再落盘。
\`\`\`
