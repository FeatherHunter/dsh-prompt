# 方向信号统一为整机（读），视口仅回落

**状态**：accepted（2026-10-02，#110 检测统一。用户原话：关时检测实际方向并选中；`auto` 现状“功能缺失”。）＋ amended（2026-10-03：退出不再还原方向，见文末改判。）

## 背景

- 桌面浏览器视口恒横屏，`auto` 跟视口等于恒横屏——在远程（手机）场景下是错误信号（ADR-0002：插件观测不到手机朝向，视口与手机无关）。
- 整机桥（`GET /_dsh/dsh-prompt/system/orientation`）已是自有读能力：锁定真切本就依赖它。再为显示另起信号源等于两套真相。
- 读与写不对称：读可缓存回落，写必须串行确认（本仓整机桥 verify+回滚既有）。

## 决定

1. **有效方向** = 显式偏好赢；`auto` 取环境方向缓存（整机桥已知值），缺席/非法回落视口推导。纯函数 `resolveEffectiveOrientation(pref, env, viewport)`，面板与设置页共用。
2. **环境缓存**住客户端远程偏好模块（内存态，附来源与时间戳）：设置页挂载预热、锁定成功复用已知结果——**零新增 spawn**。hover/面板只读缓存，永不触发网络；桥确认缺席记负缓存，本会话不再做推测性查询（用户显式锁定不受影响）。
3. **显示有效值+来源**：设置页方向行下加一行「当前：横屏（整机）/视口」，开关态同规；偏好本身不动（检测只读真值，不写真值）。
4. **方向不参与会话生命周期**（2026-10-03 改判，见下）：无进入快照、无退出恢复、无「设为默认」。

## 考虑过的选项

- **维持 auto 跟视口**——保留一个桌面恒等式，`auto` 继续名存实亡；且与“锁定先切整机”分属两个信号源，心智分裂。否决。
- **检测到啥就写偏好**——把一次读变成永久选择，污染存量（分不清哪次是检测 artifact、哪次是用户选择）。否决。
- ~~**会话覆盖改内存态（先存后恢改纯临时）**~~——2026-10-02 判为“更纯但存量改不动”，遂改走“落盘快照 + 设为默认”；**该整条分支已于 2026-10-03 作废**：退出根本不还原，UI 改的就是最终值，作废后连同“改不动”一起消失。
- **缓存轮询刷新/TTL**——自发翻转布局比滞后更惊；新鲜度由用户动作事件界定。否决。
- **手机朝向感知**——按 ADR-0002 不可观测。排除。

## 后果

- `CONTEXT.md` 方向偏好/自适应布局定义同步更新；设置页 hint 改“自动跟整机方向，无桥时跟视口”。
- 面板挂载必须是零 OS 调用（回归断言）；设置页挂载恰一次预热 GET。
- 真机验收仍需：整机横竖各转一次，确认有效值 caption 来源角标与格子同步。

## 改判：退出远程不还原方向（2026-10-03，用户拍板）

**用户原话**：「我在退出前给它选成了横屏，希望结果也是横屏，但退出之后它就还原成竖屏了。我认为，当用户锁定某个方向之后，这个行为的优先级是非常高的。此时退出远程模式，不应该去更改用户最后一次选择的屏幕状态。」

**背景**：2026-10-02 落地的 #110 把方向当「会话临时覆盖」——进入时快照 P0/O0，退出时插件层必还原 P0、OS 层按 ownership 还原 O0，另有「设为默认」入口补「恢复让存量改不动」的副作用。实测这套语义与用户心智相反：方向是**用户长期锁定的状态**，不是一次会话的临时租借。

**决定**：**方向不参与远程会话生命周期。**

- 总闸进出只翻 `enabled` 一个键，插件偏好与整机屏幕都不动；退出对整机零调用（不闪屏、不夺回控制权）。
- 用户在会话里最后选的方向（横屏/竖屏/自动）即最终值，下次进远程原样沿用，崩溃重启亦不回退。
- 随之删除：进入快照与落盘键 `__dshPromptPreRemote`、崩溃恢复分支、`shouldRestoreSystemOrientation`、「设为默认」入口及其 3 条文案。
- 遗留键 `__dshPromptPreRemote` 在加载时**无条件删一次**（幂等、零网络）：不清的话它仍会被旧路径当真相来源，把用户最后选的方向翻回去一次——正是本次要治的病。

**为什么不留「只对显式锁定不还原」**：会话内的方向变化全部来自用户点选，插件自己从不写方向（`auto` 只读不算）。所以「显式锁定」与「临时覆盖」在本仓是同一批动作，按 ownership 区分没有可分之物，只会留下「选了自动反而被还原」这种更难解释的行为。

**后果**：锁过横屏/竖屏的用户，退出远程后物理屏幕保持该方向（需自行在系统里改回）——这是「不夺回控制权」的直接代价，也是用户明确接受的。#110-3（远程关时方向/密度按钮去强调色置灰）不受影响，照旧。
